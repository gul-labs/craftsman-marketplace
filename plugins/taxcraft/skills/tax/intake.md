
# Intake Sub-Skill (Scope-Scoped Document Ingestion)

Goal: canonicalize inbound filenames, parse documents, update the scope's `tax-summary.md` + `pending-docs.md`, and cache parsed JSON in `<scope>/FY<YYYY>/.parsed/`.

Owns orchestration only. Naming rules → `naming.md`. PDF read + cache index + JSON schemas → `parsing.md`.

## Privilege Exclusion (STRICT)

Any path containing `privileged` (e.g. `*attorney-client-privileged*`) is excluded from scanning, parsing, caching, and summarization — privilege-waiver risk. Only touch such paths on explicit user instruction inside that matter's own persona folder, where the workspace defines one. See SKILL.md → "Privacy & redaction".

**Scope resolution**: before intake, know whether we're ingesting for:
- `individual/FY<YYYY>/` (personal 1040), OR
- `entities/<slug>/tax/FY<YYYY>/` (entity return, consolidating any nested disregarded SMLLCs)

Ask the user or infer from the active context.

> This sub-skill assumes the workspace profile exists (`workspace-profile/`). First-time setup lives in `init.md`.

## Entry

Triggered when:
- User says "intake docs", "ingest documents", "process files for `<scope> FY<YYYY>`", or similar
- User drops new files into the scope's folder and asks for a refresh
- SKILL.md menu option 1 → "Work on a tax year" → scope+year picked → docs not yet ingested
- User types `/intake` or says "process `_intake/`" → run **Drop-Zone Mode** below

## Drop-Zone Mode (`_intake/`)

When scope is unknown upfront — user dropped files into `_intake/` at the workspace root.

**Corporate-doc handoff**: if a file in `_intake/` is identified as a state filing, business license, BOIR confirmation, formation document, or other corporate-governance doc (not a year-scoped tax doc), do NOT route it to `tax/FY<YYYY>/source/`. Instead:

1. Resolve the entity (which entity does this filing belong to?).
2. Move it to the correct `entities/<slug>/corporate/<subfolder>/` path.
3. Hand off to `governance.md` → "Document Intake (post-filing)" for canonicalization, metadata extraction, `entity.md` update, and `_processed.log` append.

Tax-doc intake (year-scoped) continues below.

```
_intake/
  raw-k1.pdf
  some-1099.pdf
  chase-statement.pdf
```

**Flow (one file at a time, interactive):**

1. Glob `_intake/**` excluding `_processed.log` and `_unresolved/`.
2. For each file, run `$TAX_SKILL/tools/pdf-extractor/pdf_extract.py` (text → image fallback).
3. From parsed content extract: doc type, recipient/payer name, TIN, tax year.
4. Resolve TIN → scope via `workspace-profile/slugs.md`.
   - If TIN not in slugs → **pause**: "I see a document for TIN `XX-XXXXXXX` (`<payer>`). Is this for [individual / entity slug]? Want me to add it to slugs.md?"
   - If doc type unrecognizable → **pause**: show first 10 lines, ask user to classify.
5. Propose canonical destination + rename (per `naming.md`). Show one-line summary:

   ```
   raw-k1.pdf → entities/<slug>/tax/FY2024/source/k1s-received/FY2024 - K-1 - LP - <sponsor-slug>.pdf
   ```

6. Await "yes" (or correction) before moving.
7. After mv: update destination scope's `tax-summary.md` + `pending-docs.md` + `.parsed/` cache (same as Steps 3–6 of the main flow).
8. Append to `_intake/_processed.log`:

   ```
   2026-04-20 | raw-k1.pdf → entities/<slug>/tax/FY2024/source/... | parsed OK
   ```
9. Repeat for next file. Files that can't be resolved after asking stay in `_intake/` with a log note — never silently skip.

## Inputs by Scope

### Individual scope
- `individual/profile.md` — expected doc sources
- `individual/FY<YYYY>/tax-summary.md` — current state; update in place
- `individual/FY<YYYY>/pending-docs.md` — expected-doc checklist
- `individual/FY<YYYY>/source/<category>/` — actual documents. **Legacy note:** older individual workspaces used a flat `individual/FY<YYYY>/docs/`. Read from `docs/` when it exists, write to `source/<category>/`, and treat the presence of `docs/` as a pending migration (`migrate.md`) rather than a naming violation to correct mid-task.
- Cross-workspace: K-1s issued by owned entities in `entities/<slug>/tax/FY<YYYY>/issued/k1s-issued/` — reference, don't copy

### Entity scope
- `entities/<slug>/entity.md` — expected sources
- `entities/<slug>/tax/FY<YYYY>/tax-summary.md` — current state
- `entities/<slug>/tax/FY<YYYY>/pending-docs.md`
- `entities/<slug>/accounts/<account-slug>/` — **raw** bank/CC/brokerage statements + full-history CSV export (belongs to the account, not to any tax year)
- `entities/<slug>/tax/FY<YYYY>/source/` — **year-scoped** source: K-1s received, 1099s received, W-9s, receipts, and per-account year-filtered CSV slices under `bank-cc/<account-slug>.csv` (generated by `tools/chase-statement-parser/` or equivalent)
- Nested `entities/<slug>/disregarded/*/accounts/` — SMLLC-level accounts follow the same pattern at their own level

## Flow

### 0. Canonicalize filenames (MUST run before Step 1, default on every touch)

Audits of real workspaces show near-zero files actually follow `naming.md` — nothing enforced it. Treat sweep + normalize as the **default** action whenever a scope folder is touched, not an opt-in step to skip when files "look fine."

Glob inbound docs:
- Individual: `individual/FY<YYYY>/{source,docs}/**/*.{pdf,csv,xlsx,png,jpg}` (excluding `.parsed/`) — `docs/` is the legacy location, scanned but not written to
- Entity: `entities/<slug>/tax/FY<YYYY>/source/**/*` + nested `disregarded/**/source/`

For each file whose name does NOT match canonical form (`naming.md`):

1. Sniff doc type (filename hints + `pdftotext -layout` header — see `parsing.md`).
2. Resolve slugs via `workspace-profile/slugs.md`. Unknown party → ask user, add row to `slugs.md`, then proceed.
3. Determine tax year from doc header (authoritative) vs. folder (fallback). Mismatch → move to correct `FY<YYYY>/`.
4. Propose rename batch (legacy → canonical). Show table, await approval, execute via `mv`, verify.

Already-canonical files pass through. Receipts / W-9s / governance docs follow their own canonical forms in `naming.md`.

**Duplicate detection (flag for review, never auto-delete):**
- `(1)` / `(2)` copy-suffix from browser or Finder re-downloads
- Device-sync conflicts (e.g. `... (MacBook-Pro's conflicted copy)`, `...-<device-name>`)
- Extension casing/doubling: `.pdf.pdf`, `.Pdf`, `.PDF`

List these in the rename-batch table as "possible duplicate of `<canonical target>`" and queue for user confirmation alongside the renames. Even an exact-sha256 duplicate is never deleted without explicit user confirmation (`naming.md` "Collision rules").

### 1. Classify

Match against canonical filenames per `naming.md`. Since all files are now canonical, classification is deterministic: `FY<YYYY> - <DocType> - ...` → `<DocType>`. Non-matching files after Step 0 indicate a Step 0 gap — do not force-classify; append to `open-questions.md`.

### 2. Check parse cache (per `parsing.md`)

Look up by `source_path` in `.parsed/_index.json`. If size + sha256 match → read parsed JSON, skip.

### 3. Parse new docs

Route by doc type to the dedicated parser — do not run everything through manual `pdf-extractor`:

| Doc type | Parser | Invocation |
|---|---|---|
| K-1 (1065 / 1120-S), incl. multi-K-1 packages | `tools/k1-parser/` | `python3 -B "$TAX_SKILL/tools/k1-parser/k1_parser.py" "<path>" [--multi] [--json] [--write]` |
| Filed return (1065 / 1120 / 1120-S) | `tools/return-parser/` | `python3 -B "$TAX_SKILL/tools/return-parser/return_parser.py" "<path>" [--json] [--no-confirm]` |
| IRS transcript (Account / Return / Wage & Income / Record / Non-Filing) | `tools/transcript-parser/` | `python3 -B "$TAX_SKILL/tools/transcript-parser/transcript_parser.py" "<path>" [--json]` |
| IBKR statement CSV | `tools/ibkr-parser/` | `python3 -B "$TAX_SKILL/tools/ibkr-parser/ibkr_parser.py" <statement.csv> [--pdf <statement.pdf>] [--no-confirm]` |
| Chase bank / credit-card statement or CSV | `tools/chase-statement-parser/` | library-only — invoke via the entity's `books/transaction-ledgers/regenerate.py` driver calling `build_ledgers()` (see tool README) |
| W-2, W-2G, 1099-INT/DIV/B/NEC/MISC/R/G/K/SA, 1099-Composite, SSA-1099, 1098, 1098-T, 1098-E, 5498, 5498-SA, 1095-A | `tools/form-parser/` | `python3 -B "$TAX_SKILL/tools/form-parser/form_parser.py" "<path>" --type <doc-type> --vision-prompt` → read the PNGs, fill the skeleton → `... --merge <vision.json> --json [--write]` (`parsing.md` rungs 0–4) |
| Everything else (receipts, scans, letters, notices, W-9, statements without a dedicated parser) | `tools/pdf-extractor/` | `python3 -B "$TAX_SKILL/tools/pdf-extractor/pdf_extract.py" "<path>" [--mode form] [--force-image] [--pages N-M] [--json]` |

Then per `parsing.md` (PDF discipline, text-quality gate, vision + text merge, per-doctype schemas). Run `tools/parse-verify/verify.py` on the result before Step 4; a CRITICAL finding or a non-empty `_extraction.review_required` means the document is not final. Never use the built-in Read tool on structured PDFs. Never silently skip a load-bearing doc.

### 4. Write parsed JSON + update index

Per `parsing.md` index shape. Slug format per `naming.md` ("Parsed cache slugs").

### 5. Update `tax-summary.md`

Find the matching section (e.g., "### W-2") and append a row. Idempotent — update in place if row for same source exists; a row is a fact, and replacing it is not a supersession event. If the new document changes a *conclusion* (a treatment, a position, an election), that is a decision memo per `supersession.md` §3, not a row edit. Keep formatting consistent with template. Mask SSN/EIN/account numbers to last-4 per SKILL.md → "Privacy & redaction".

### 6. Update `pending-docs.md`

For each newly ingested doc, check off the matching `- [ ]` expected item and move to **Received** section with date.

Unexpected docs → add info note: *"Unexpected: `<doc>` from `<payer>`. Add to profile/entity config? (permanent) or one-off?"*

### 7. Flag gaps

After ingest, surface:
- Remaining unchecked pending items
- Anomalies (negative wages, $0 basis on covered lots, K-1 box 20 code Z missing, cash flow mismatches)
- Mismatches between expected and seen sources (e.g., W-2 from new employer not in profile)
- For entity scope: if disregarded SMLLCs exist, confirm their own source docs are also ingested

## Entity-Specific Intake Notes

### Disregarded SMLLC documents

When a K-1 is issued to an SMLLC's name, verify (see `entities/disregarded.md`):
- Partner name should be the regarded owner, NOT the SMLLC
- Partner EIN should be the regarded owner's EIN

If the K-1 is incorrectly issued in the SMLLC's name + EIN, request a corrected K-1. Do NOT silently import — it creates downstream IRS matching errors.

### 1099 to the entity

An entity receiving 1099-NEC, 1099-MISC, 1099-INT, 1099-DIV should match the recipient TIN to the regarded entity's EIN. Mismatches are a frequent issue when a disregarded SMLLC's EIN was accidentally used on a W-9. Flag and ask user to request a corrected 1099.

### Transaction CSVs and bank statements (entity scope)

Raw account data lives at **account level**, not year level:
- Monthly PDF statements → `entities/<slug>/accounts/<account-slug>/statements/`
- Full-history CSV export → `entities/<slug>/accounts/<account-slug>/all-transactions.csv`
- Check images, wire confirmations → `entities/<slug>/accounts/<account-slug>/check-images/`

Year-filtered transaction CSVs live in `tax/FY<YYYY>/source/bank-cc/<account-slug>.csv`. These are **derived**, produced by `tools/chase-statement-parser/` (for Chase) which reconciles PDF statements against the CSV, validates against stated balances, and splits into per-year slices. Regenerate any time from the raw source; never hand-maintain.

Intake only loads parsed-cache metadata into the index; **actual classification and P&L generation happens in `entities/c-corp.md` / `entities/partnership.md` / `entities/s-corp.md` at close time**, using the year-filtered slice as input.

## Receipt Intake Rules

### Image handling (HEIC / JPG / PNG)

When receipts arrive as phone photos (HEIC, HEIC+HEIC duplicate angles, etc.):

1. **Convert HEIC → JPG** to conserve space. Use:
   ```bash
   magick "<input>.HEIC" -resize 60% -quality 82 "<output>.jpg"
   ```
   Typical savings: ~55% vs HEIC. Keep quality ≥ 80 so all text remains legible.

2. **Keep only the best image** when multiple shots of the same document exist. "Best" = flattest, most complete, full text visible top-to-bottom. Delete the others after conversion.

3. **Naming**: use the same base name as the event/PDF receipt, appended with `- Itemized Check.jpg` (or `- Receipt.jpg` if no PDF). Example:
   ```
   <Entity> - Investor Dinner - <Venue> - 4-24-2026 - Itemized Check.jpg
   ```

4. **Keep the PDF credit-card slip too** when it exists — it proves the exact charge amount on the card statement. The photo proves what was ordered. Both live in `tax/FY<YYYY>/source/receipts/`.

### §274(d) Substantiation

Full doctrine (receipt threshold, five mandatory elements, 50% limit, split-bill handling) → `scenarios/meals-substantiation.md`. Read it before ingesting any meal/entertainment receipt.

**Where to record:** receipt files prove elements 1–3 (amount, date, place). Elements 4–5 (business purpose + attendees) must be in the expense log entry, NOT just in your head — never solely in memory. Log path:
- Entity: `entities/<slug>/tax/FY<YYYY>/expenses-log.md`
- Individual: `individual/FY<YYYY>/expenses-log.md`

If recorded in a separate memo, cross-reference the filename.

### Expense log fields — minimum required

Each row must capture:

```
Date | Vendor | Category | Gross | Deductible | Payment | Business Purpose | Attendees | Receipt file(s)
```

If the Notes column is getting long, break attendees + purpose into a sub-section below the table row (see the expenses-log template). Mask SSN/EIN/account numbers to last-4 per SKILL.md → "Privacy & redaction".

## Missing-Doc Workflow

If the profile/entity-config implies a doc should exist but no file matches, ask:

Update `<scope>/FY<YYYY>/pending-docs.md`.
